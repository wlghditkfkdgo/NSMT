# 2026-09-15 PopulationLIF v2 결과 브리핑 — 1차 H96

얕은 patch SNN의 H96 36회 학습 완료. H720/TCN/PatchTST/TSMixer는 최초 pipeline의 후처리 assertion으로 아직 미실행이며, 후처리 복구 후 이어서 실행한다. 전체 288회 완료로 해석하면 안 된다.

검색 없음에서 heterogeneous MSE .378484 vs homogeneous .395326: −4.26%. Heterogeneous dense .377628은 off 대비 −.23%, sparse .381363은 off 대비 +.76%, dense 대비 +.99%다. Sparse−dense의 dataset-macro ΔMSE는 세 seed 모두 양수다. Homogeneous sparse는 off 대비 −.96%로 개선되지만 주로 ETTh2에서 나온다. 두 dataset/세 seed만으로 보편적 효과나 통계적 유의성을 주장하지 않는다.

Heterogeneous sparse는 첫8test windows 진단에서 슬롯 density .326631, empty read fraction .149941로, 선택적 사용/비사용은 동작했다. 같은 sparse checkpoint에서 retrieval을 끄면 MSE는 평균 .006680 증가한다. 학습된 모델이 검색을 사용한다는 관찰과 검색 없이 따로 학습한 대조군보다 좋은가는 서로 다른 질문이며, 이번 결과는 후자의 개선을 보이지 않았다.

36회 중1회가 최대30epoch 도달. Best epoch은0-based1–29; 모두 최저 validation MSE checkpoint를 복원했다.

후처리 원인: frozen layers.py의 weight=p/max(real_mass,1e-12) 때문에 아주 작은 양의 dense mass에서는 weight 합이1보다 작다. 기존 audit의 sum(lag_mass)=1-empty 가정이5개 dense run에서 실패했다(평균 mass 차이 최대 .0177044). 모델/학습/평가 source10개와 checkpoint/원시run 결과는 변경하지 않았다. 새 audit은 모든 checkpoint에서 sum(weight)=real_mass/max(real_mass,1e-12)를 직접 재검증한다. Lag/entropy의 floor 관련 해석 제한을 README에 수정했다. 전체 artifact/statistics audit 및 대표 heterogeneous sparse ETTh1 seed7의 fresh GPU 전체 test+off/uniform/recent MSE/MAE(atol1e-12) 통과.

- Sparsemax는 일부 weight를 정확히0으로 만들 수 있지만 매 query의 sparsity를 보장하지 않는다. 실제 density/empty rate를 함께 읽는다.
- 실제 read 분모는 max(real_mass,1e-12)이다. 아주 작은 양의 real mass에서는 weight 합이1보다 작다. Lag mass/mean lag/entropy 해석에 이 floor를 반영해야 하며 check_read_mass.json에서 각 checkpoint로 실제 수식을 재검증한다.
- Off/dense/sparse의 nominal parameter/초기값은 같고 off의 retrieval 파라미터는 미사용이다. Homogeneous는 redundant-state 대조다.
- off/uniform/recent는 같은 checkpoint의 평가 개입이다. uniform/recent는 null을 우회하여 과거 후보를 강제 선택하고 gate를 재계산한다.
- 서로 다른 backbone은 용량/연산이 다르다. PatchTST와 TSMixer는 causal population-spiking 변형이며 원 논문 재현이 아니다.
- 알려진 slot의 operator 검사는 통과했지만 end-to-end synthetic recall 학습/에너지 측정/정답 ETT lag 검증은 not run.
- 과거slot mask는 raw input의 후속 recurrent-state 영향을 삭제하지 않는다. Dense search와 sparse use는 별개다.
- 이전 v1 결과는 scorer/gate/budget 등이 달라 sparsemax만의 효과를 비교하는 대조가 아니다. v2 dense와 sparse가 해당 대조다.
