# 브리핑

이 저장소의 연구 진행 상황을 **연구자 본인**에게 보고한다. 동료나 외부 독자가 아니라, 이 실험을 직접 설계한 사람이 읽는다.

## 먼저 상태를 모은다 (추정하지 않는다)

브리핑은 **읽은 것만** 말한다. 아래를 실제로 확인한 뒤 쓴다.

```bash
# 지금 돌고 있는가
pgrep -af 'snn_recall/bin/python (train|calibrate)' || echo "없음"

# 어디까지 왔는가
git log --oneline -3 ; git status -sb | head -1

# 감사가 새로 말한 것이 있는가  (사용자의 상시 지시)
git diff --stat NSMT/docs/ASSESMENT.md
grep -n '^## ' NSMT/docs/ASSESMENT.md | tail -3

# 최근 기록
tail -80 docs/PROJECT_LOG.md
```

백그라운드 작업이 있으면 그 출력 파일을 직접 읽는다. **끝나지 않은 작업의 결과를 예상해서 쓰지 않는다.**

## 형식

고정된 틀보다 그때 중요한 것이 앞에 오게 한다. 다만 아래는 대체로 지킨다.

1. **`## 한 줄로`** — 지금 상태를 한 문장으로. 여기만 읽어도 핵심이 전달되어야 한다.
2. **지금 돌고 있는 것** — 없으면 "없음"이라고 먼저 밝힌다.
3. **핵심 발견** — 수치는 표로. 무엇을 말하고 무엇을 말하지 않는지 함께.
4. **아직 안 된 것** — 숨기지 않는다.
5. **감사 상황** — 새 지적이 있으면 사실 여부를 먼저 확인했는지 밝힌다.
6. **다음** — 한두 줄.

## 말투와 용어

사용자가 명시적으로 요구한 사항이다.

- **알아들을 수 없는 용어를 쓰지 않는다.** 과거에 "regime", "U[6,16]" 같은 표현으로 지적받았다. 불가피하면 **그 자리에서 풀어서 설명**한다.
  - "sparsemax" → "가장 관련 있는 것만 남기고 나머지를 0으로 만드는 함수"
  - "M_eff" → "정답 위치에 실리는 비중"
  - "G" → "정답을 알려줬을 때 얻는 개선 중 몇 %를 가져왔는가"
  - "G11" → "상태가 너무 커지면 학습을 멈추는 안전장치"
- 짧은 문장. 표를 적극적으로 쓴다.
- 영어 지표 이름을 쓸 때는 한 번은 한국어로 풀어준다.

## 정직성

이 프로젝트에서 가장 중요한 부분이다.

- **탐색과 확증을 반드시 구분한다.** 현재 결과는 대부분 seed 1개짜리 탐색이다. "입증됐다"고 쓰지 않는다.
- **나쁜 결과를 먼저 쓴다.** 기준 미달, 실패한 후보, 안전장치 위반은 성과와 같은 비중으로 다룬다.
- **내 실수를 감추지 않는다.** 감사가 찾은 결함과 내가 철회한 주장을 브리핑에 포함한다. 이 프로젝트에서는 그것이 진행 상황의 일부다.
- 수치는 **로그나 artifact에 있는 값 그대로**. 기억으로 쓰지 않는다.

## 길이

한 화면에서 두 화면 사이. 모든 것을 넣지 말고 **지금 결정에 필요한 것**을 넣는다. 세부는 `docs/PROJECT_LOG.md`에 있으므로 거기를 가리키면 된다.
